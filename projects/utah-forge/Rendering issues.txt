
We are not rendering the full model density.
The full Phase 3 MT model has about 1,094,940 rows. The current point preview intentionally samples 90,000 points so the browser does not choke. That is a QA/display preview, not the full-density model.

The main visible layer is slices, not a full volume cloud.
The better-looking layer is utah-forge-mt-resistivity-slices: six horizontal slices and two vertical sections. Those are binned/averaged presentation surfaces from the model, not every source cell rendered as a dense 3D block/point field.

MT resistivity is not naturally a dense visual point cloud like LiDAR.
It is an inversion model. The “cloud” in reports may be all model cell centers, a voxel/block rendering, or a denser scientific viewer output. Our current GeoSee view is a browser-safe preview of that model.

What you may be missing: we have proven the data pipe and the real coordinate/value basis, but we have not yet built the full-density visualization mode.

Best next options, depending on the visual target:

For visual density: build a tiled/all-cell point preview from the full 1.09M positive model rows.
For a more professional geophysics look: build voxel/block or semi-transparent volume sections.
For presentation clarity: add more slice planes and tighter authored page presets.
For report matching: compare the report figure type: full cell cloud, section, voxel, interpolated volume, or external scientific render.
My read: nothing is “wrong” yet. What you are seeing is the current deliberate lightweight preview stage. If the goal is to match the report’s full-density geophysical visuals, the next step is a higher-density/tiled renderer or volume/slice renderer, not more source acquisition.
